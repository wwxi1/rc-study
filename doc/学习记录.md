1. **git init**：本地初始化Git仓库

2. 关联github远程仓库

3. **git add .git** ：把当前文件夹改过的文件加入暂存区

4. **git commit -m “ xxxxxx”**  :把暂存区的文件打包成一个本地版本快照,标注xxxxxxx，要做好标注且必须做标注，否则无法提交。

5. **git checkout -b xxxxxxxxx**:新建一个名为xxxxx的分支
6. 改后重复3,4，然后g**it checkout main**：切回主分支
7. **git log --oneline**  :以精简的单行格式展示当前分支的提交历史,可以从这里看到哈希值。可以加参数限定查看范围，比如   **git log --oneline -n 5**   只显示最近5条提交记录。（--online 作用是使单行显示）

8. **git diff main xxxxxx**: 比较main分支与xxxxx分支的区别

9. **git merge xxxxx**：把xxxx分支的改动整合到当前分支上（一般是主分支）

10. **push**：推送到远程仓库

- **pull** 从远程仓库拉取内容上

##  8.7  工具链记录



**在 `MDK-ARM` 目录里找到 `.o`、`.axf`、`.hex` 文件**

**回答：**  

- **F7` 完成了哪几步；**
- **F8`把什么文件写进了芯片；**
- **为什么改完代码必须重新编译再下载**



#### 按下F7 “编译” 作用

#### **1. 编译**与汇编：遍历工程里所有加入Group的.c文件，把每个C代码编译成对应的`.o`机器码文件

#### **2. 链接**：把所有生成的`.o`文件、STM32库的目标文件链接，最终生成`.axf`可执行文件。

**3. 后处理**：**把`.axf`文件，转换生成`.hex`文件**

####  按下F8下载作用

把`.hex`文件程序数据烧录进STM32芯片片内的Flash中

​	Keil调试器会直接读取`.axf`文件里的完整地址和程序信息，也可以直接加载独立的`.hex`文件，最终把程序二进制内容写入芯片的0x08000000起始的片内Flash区域。

#### 3. 改完代码必须重新编译再下载的原因

​	修改的是`.C`源代码，这个代码本身不能被STM32芯片直接识别运行。只有重新执行F7编译，Keil才会把你修改后的C代码重新编译为新的机器码，生成更新后的`.o`、`.axf`、`.hex`文件，此时下载到芯片里的才是你修改后的新程序**；如果不重新编译直接下载，Keil只会把之前旧版本的程序烧录进去，你的代码改动完全不会生效。**



## 配置工程步骤：

1. 新建group
2. 把写好的文件add进该group
3. 在keil5 魔法棒图标（设置）的c/c++选项卡的`include path`中添加该文件的inc文件地址（其中包含的一般是该文件的头文件）
4. F7编译，链接外设后F8下载



## 析

1. 系统需要从path中找到程序的头文件来进行链接，如果没有配置或配置错误，在链接时就会找不到目标地址，从而出现报错。 如keil5 中的`include path`
2. inc文件一般包含头文件，而src文件一般包含函数实现，即函数具体内容。如果没有src文件，程序运行时就会找不到函数内容。



运行时遇到的报错：

1. 插入ST-LINK 接口后，下载报错：

   原因：当前Keil工程里的调试器配置选错了，选成了ULINK2/ME，而你实际用的是ST-Link，两者不匹配才会提示找不到设备

   解决方案：在Keil工程，点击顶部工具栏的魔法棒图标切换到**Debug**选项卡，在左上角把默认的「ULINK2/ME Cortex Debugger」改成「ST-Link Debugger」

   

2. 移除 `hardware Group/Src` 里的 `buzzer.c` 和 `led.c`后：

 ```
  ArmClang: error: no such file or directory: '../hardware/src/buzzer.c'

  compiling buzzer.c...
  ArmClang: error: no such file or directory: '../hardware/src/led.c'
  ArmClang: error: no input files
 ```

​       原因：函数实现没了

3. 移除 Include Paths 里的 `..\hardware\inc`后：

​		**报错**

​     原因：编译链接时找不到 `buzzer.h` / `led.h` 之类的头文件

4. 再次打开vs code时发现git无法连接：

   原因：git的路径发生了变动

   解决方案：在计算机--属性--高级选项--环境变量--系统变量-Path中进行更改调整
